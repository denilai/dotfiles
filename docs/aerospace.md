# AeroSpace

[AeroSpace](https://github.com/nikitabobko/AeroSpace) — тайлинговый менеджер окон
для macOS. Окна сами делят экран, воркспейсы свои (не macOS Spaces), управление с
клавиатуры.

## Где что

| Что | Где |
|---|---|
| Конфиг | `.aerospace.toml` в этом репозитории |
| Живой файл | `~/.aerospace.toml` — симлинк на конфиг из репозитория (`scripts/link.sh .aerospace.toml`) |
| Шпаргалка | [aerospace-cheatsheet.html](aerospace-cheatsheet.html), открывается скриптом `scripts/aerospace-cheatsheet.sh` |
| Установка программы | `brew install --cask nikitabobko/tap/aerospace` |
| Правила и подводные камни | скил `aerospace` (`~/.claude/skills/aerospace/SKILL.md`) |
| Раскладка клавиатуры, от которой строятся привязки | `~/repos/personal/corne-keyboard-layout` (Corne, `config/corne.keymap`) |

Конфиг правится только в репозитории. Перечитывается сам (`auto-reload-config`),
вручную `aerospace reload-config`.

## Состояние конфига

- **Воркспейсы по ролям:** `T` терминал и редактор (Terminal, VS Code, Fork, Docker Desktop,
  Notes, TextEdit), `B` браузер (Chrome, OpenVPN Connect, Iru Self Service), `P` Personal
  (Vivaldi, Bitwarden, Lens), `D` Obsidian и чат-приложение, `E` дом и развлечения (VLC, Photos,
  Home, iPhone Mirroring; буква E, потому что H занята фокусом влево), `F` системные
  окна (Finder, System Settings, Activity Monitor; плавающие), `S` Slack, Calendar, Gmail,
  Google Calendar, Google Meet (три последних — приложения Chrome со своими id); `1 2 3` для
  разового. Приложения попадают на свой воркспейс правилами `[[on-window-detected]]`
  в момент появления окна.
- **Модификатор — Hyper** (`ctrl-alt-shift-cmd`, удержание правого Del thumb или левого
  Enter thumb на Corne: буквы любой половины нажимаются с Hyper противоположной руки):
  `H J K L` фокус, буква роли (`T B P D F S E 1 2 3`) — воркспейс, `Tab` — прошлый
  воркспейс, `V` `A` `G` — тайлы, аккордеон, плавающее (не `/` `,` `.`: macOS забирает ⌃⌥⇧⌘ с этими
  клавишами раньше AeroSpace, Karabiner-EventViewer их видит, а AeroSpace нет), `Enter` — на весь воркспейс (`fullscreen`:
  внешние зазоры `gaps.outer` сохраняются, с одним окном размер почти не меняется, с несколькими
  окно закрывает остальные), `=` — выровнять размеры.
- **Режимы:** `Hyper+M` — перенос окна (`H J K L` двигают, буква или цифра отправляет на
  воркспейс), `Hyper+R` — размер, `Hyper+;` — сервисный: одна клавиша без модификаторов и сам
  выходит (`F` на весь воркспейс AeroSpace, повторно — назад, `G` плавающее, `H J K L` вложить окно с соседом, `R` сбросить раскладку, `B` выровнять,
  `T` тайлы, `A` аккордеон, `Enter` на весь воркспейс с зазорами, `E` вплотную ко всей видимой
  области (`fullscreen --no-outer-gaps`, меню и Dock остаются), `N` нативный fullscreen macOS
  (отдельный Space, меню и Dock скрыты; `scripts/aerospace-native-fullscreen.sh`: включает или
  выключает по состоянию окна, залипшее расклеивает, плавающее окно после выхода остаётся
  плавающим), `X` расклеить залипшее окно
  (`scripts/aerospace-unstick.sh`), `Q` закрыть текущее окно,
  `Esc` перечитать конфиг). **Зазоры в fullscreen** отдельно не
  настраиваются: либо `fullscreen` (внешние зазоры сохраняются, их размер задают `gaps.outer.*`),
  либо `fullscreen --no-outer-gaps` (внешних зазоров нет); внутренних зазоров у одного окна нет.
- **Слой Nav на Corne** шлёт ⌃←/→/↑/↓ (раньше Spaces, Mission Control, App Exposé). AeroSpace
  их перехватывает: Nav+`;` и Nav+`'` — прошлый и следующий воркспейс по кругу (порядок
  алфавитный: `1 2 3 B D E F P S T`), Nav+F — на весь воркспейс (с зазорами), Nav+G — плавающее ↔ тайл.
  Побочный эффект: настоящие Ctrl+стрелки в приложениях не доходят. Чтобы AeroSpace вообще
  получал эти клавиши, четыре системных сочетания macOS (Move left / right a space, Mission
  Control, Application windows) отключены: `scripts/macos-spaces-shortcuts.sh off`, вернуть
  `... on` (копия настроек в `~/.local/state/dotfiles/`). Пока они включены, macOS обрабатывает
  ⌃←/→/↑/↓ раньше AeroSpace, и привязки `ctrl-left/right/up/down` не срабатывают.
- **Шпаргалка по F20:** привязка `f20` запускает `scripts/aerospace-cheatsheet.sh toggle`;
  F20 шлёт комбо двух крайних sticky Shift третьего ряда Corne.
- Зазоры 8 px, `start-at-login = true`, `auto-reload-config = true`.
- **Действия с окном** (закрыть, спрятать, перенести, размер, fullscreen, плавающее и все дубли
  сочетаний) собраны в шпаргалке, блок «Окно: закрыть, свернуть, перенести». Закрытие через AeroSpace
  только `Hyper+;`, `Q` (отдельного `Hyper+Q` нет, чтобы не закрыть окно случайно); свернуть (`⌘M`)
  не стоит: AeroSpace не видит свёрнутые окна.
- **Системные настройки macOS под AeroSpace** (меняются скриптами, вернуть — `on`):

  | Что | Состояние | Как |
  |---|---|---|
  | Сочетания ⌃←/→ (Spaces), ⌃↑ (Mission Control), ⌃↓ (App Exposé) | выключены | `scripts/macos-spaces-shortcuts.sh off` |
  | Встроенный тайлинг: перетаскивание к краям и к строке меню, тайлинг с ⌥ | выключен | `scripts/macos-window-tiling.sh off` |
  | Двойной клик по заголовку окна (Zoom/Fill) | ничего не делает (`None`) | тот же `scripts/macos-window-tiling.sh off` |
  | Mission Control: окна сгруппированы по приложениям | включено | `defaults write com.apple.dock expose-group-apps -bool true && killall Dock` |
  | Spaces не переставляются по использованию (`mru-spaces`) | выключено | `defaults write com.apple.dock mru-spaces -bool false && killall Dock` |

  Без этого macOS сама растягивает окна или перехватывает клавиши раньше AeroSpace. Состояние
  тайлинга и двойного клика: `scripts/macos-window-tiling.sh` без аргумента.
- **Рамка активного окна: выключена.** AeroSpace рамок сам не рисует, раньше стоял JankyBorders
  (`.config/borders/bordersrc` в репозитории, красная рамка 4,8 px). Выключен
  (`brew services stop felixkratz/formulae/borders`), потому что у него есть артефакт: над верхним краем
  окна рисуется тонкая светлая линия по верхней границе окна-рамки (у окон-рамок запас 13 px, верх
  заходит на строку меню). Не помогли `hidpi`, `ax_focus`, `style`, увеличенный `gaps.outer.top` и
  сборка из HEAD (a7297ca): линия то пропадает, то возвращается после смены фокуса. С остановленным
  `borders` линии нет (проверено снимками экрана). Включить обратно: `brew services start
  felixkratz/formulae/borders`. Фокус и так виден по цвету кнопок окна и яркости заголовка.

## Несколько мониторов

Правила и подходы (настройки в конфиге пока не заведены):

- **Монитор показывает, воркспейс хранит.** На каждом мониторе в момент времени виден ровно один
  воркспейс; воркспейс виден максимум на одном мониторе. Один воркспейс на два экрана или окно на два
  экрана не растянуть, данные не дублируются.
- **Перетаскивание окна на другой монитор** переносит его в воркспейс, видимый на том мониторе
  (`on-window-detected` срабатывает только при появлении окна). Вернуть: `move-node-to-workspace <WS>`.
- **`workspace X`** переключает воркспейс только на сфокусированном мониторе. Одной командой оба
  монитора не переключаются; для этого нужен биндинг из двух команд (`focus-monitor` + `workspace`).
- **Окна одной роли на двух экранах** = два воркспейса (например `T` и `T2`), по одному на монитор.
  Подход: пары воркспейсов по ролям плюс биндинг «показать пару».
- **Привязка к монитору:** секция `[workspace-to-monitor-force-assignment]`, значение — имя, `main`,
  `built-in` или список с запасными вариантами (`T = ['main', 'built-in']`).
- **Монитор отключён:** окна не теряются, воркспейсы переезжают на оставшийся экран и доступны теми же
  клавишами; при подключении AeroSpace старается вернуть их обратно. Раскладка тайлов хранится в памяти
  AeroSpace и пропадает при его перезапуске.
- **macOS:** включить «Displays have separate Spaces» (Mission Control).
- **Проверка:** `aerospace list-workspaces --monitor all --visible`,
  `aerospace list-windows --all --format '%{workspace} | %{app-name} | %{window-title}'`.

## Шпаргалка

`docs/aerospace-cheatsheet.html` — белая страница с воркспейсами, сочетаниями и тем, что
нельзя забыть. Окно показывает `KeymapView.app` из репозитория Corne
(`~/Applications/KeymapView.app`, собирается его `scripts/keymap-view.sh build`): окно поверх
остальных и с фокусом, Esc или Cmd+W закрывают, повторное комбо тоже. Заголовок окна у него
«Corne keymap». Окно плавающее и остаётся на текущем воркспейсе: правило `[[on-window-detected]]`
делает его плавающим, а скрипт кладёт на воркспейс, откуда его вызвали, и возвращает туда фокус
(иначе из пустого воркспейса AeroSpace перескакивал на воркспейс последнего активного окна);
при закрытии перескока тоже нет. Так же ведёт себя шпаргалка по Corne (`scripts/keymap-view.sh`
в репозитории Corne). Без этого приложения шпаргалка откроется в браузере по умолчанию. **При
изменении конфига, ролей или сочетаний обновлять шпаргалку.**

## Что нужно знать

- Окна видны AeroSpace только с разрешением Accessibility (System Settings →
  Privacy & Security). Если `aerospace list-windows --all` пуст, а
  `aerospace list-apps` нет, разрешение «протухло»: выключить и включить
  переключатель, перезапустить AeroSpace.
- Проверка, что конфиг загрузился: `aerospace list-modes` (`main`, `move`, `resize`,
  `service`). Привязку можно проверить без клавиатуры: `aerospace trigger-binding --mode main
  ctrl-alt-shift-cmd-t`.
- Правила приложений срабатывают один раз при появлении окна: открытые заранее остаются где были.
- **Приложения без правила** (например Preview) правилами не фильтруются: окно открывается на текущем
  воркспейсе и само встаёт в тайлы (только диалоги и нестандартные окна AeroSpace считает
  плавающими). Правило нужно лишь чтобы закрепить приложение за воркспейсом или сделать его
  плавающим; id приложения: `aerospace list-apps`. Перенести окно вручную: `Hyper+M`, затем буква
  воркспейса. Видеоплееры с фиксированным соотношением сторон (у VLC в тайле высота меньше) удобнее
  делать плавающими. Окна запроса прав Admin By Request плавающие и остаются на текущем воркспейсе.
- **Правило действует на все окна приложения,** не только на главное: «картинка в картинке» из
  браузера или маленькое окно быстрого ввода уедут на воркспейс приложения. Исключение — правило
  выше общего, по `if.window-title-regex-substring`, с `layout floating` и без переноса (AeroSpace
  применяет первое подходящее правило).
- **«Залипшее» окно.** Если AeroSpace видит окно как `macos_native_fullscreen` (хотя приложение уже
  не в fullscreen, было с VLC), команды раскладки отвечают «Can't change layout for macOS minimized,
  fullscreen windows or hidden apps», и окно не тайлится и не ресайзится. Лечение: сервисный режим, `X`
  (`scripts/aerospace-unstick.sh`): окно уходит на другой воркспейс и обратно, AeroSpace заново
  определяет его как обычное, раскладка (тайл или плавающее) и фокус сохраняются. Не включать
  `macos-native-fullscreen on` на таком окне: оно уходит за экран (сервисный `N` этого не делает).
- Docker Desktop в конфиге плавающий (`layout floating` в правиле): его минимум окна около 940×600,
  в плитке половины экрана он вылезал за край. Так же будет с любым окном, у которого минимум
  больше плитки: AeroSpace не может его сжать, окно выходит за экран.
- Деление экрана: `Hyper+V` переключает раскладку контейнера (рядом ↔ друг под другом). Вложить окно
  с соседом: сервисный режим (`Hyper+;`), затем `H/J/K/L` (`join-with`). Команду
  `split` использовать нельзя: при `enable-normalization-flatten-containers = true` она не работает,
  и AeroSpace отказывается загружать такой конфиг (показывает окно «Config Diagnostics»).
  `aerospace reload-config` печатает ошибку, если конфиг не принят, и молчит, если всё в порядке.
- Зелёную кнопку окна (нативный fullscreen macOS) лучше не использовать: она выносит окно в
  **отдельный Space** (виртуальный рабочий стол: окно на весь экран, меню и Dock скрыты, в Mission
  Control своя миниатюра). Вместо неё `Hyper+Enter` (`fullscreen`) или `Hyper+;`, `E` (вплотную); когда нативный fullscreen
  всё же нужен, `Hyper+;`, `N` (повторно — выход). Проверено на
  тестовом окне: AeroSpace оставляет окно в его воркспейсе с раскладкой `macos_native_fullscreen`;
  `Hyper+<воркспейс>` уводит на обычный рабочий стол (окно остаётся в своём Space); вернуться в него
  можно свайпом по трекпаду или через Mission Control (⌃←/→ как Spaces отключены); выйти:
  `aerospace macos-native-fullscreen off`, Esc в видеоплеере, Ctrl+Cmd+F. Видео в браузере
  (`f` на YouTube) обычно тоже уходит в такой Space. Без нового Space: `Hyper+Enter`, режим
  «кинотеатр» (`t`) и автоскрытие Dock и меню в настройках macOS.
- Если AeroSpace завершили жёстко, окна неактивных воркспейсов остаются за краем
  экрана: запустить AeroSpace снова. Временно отключить тайлинг:
  `aerospace enable off`.
- **Привязок на Alt нет:** они перехватывают Option+буква (é, «–», «≠») и срабатывают от home-row Alt
  на Corne (S, L) при быстрой печати. Модификатор — только Hyper.
- **⌃⌥⇧⌘ с `/` `,` `.` не использовать:** это системные сочетания диагностики macOS, до AeroSpace они
  не доходят. ⌃⌥⇧⌘. запускает sysdiagnose: через пару минут в `/private/var/tmp` появляется архив
  `sysdiagnose_*.tar.gz` (сотни МБ, логи системы), его можно удалить.
- **Cmd+H** (скрыть приложение) не прячет окна мимо воркспейсов: `automatically-unhide-macos-hidden-apps
  = true`, AeroSpace сразу показывает скрытое приложение снова. Свернуть окно (Cmd+M) по-прежнему можно.
- **Mission Control** показывает окна всех воркспейсов (AeroSpace прячет их в угол экрана, а не
  сворачивает), клик по окну переключает на его воркспейс. Окна сгруппированы по приложениям:
  `defaults write com.apple.dock expose-group-apps -bool true && killall Dock`, иначе мелкие окна из
  угла теряются.
